# Як користуватися Otack Manager

Вітаємо в **Otack Manager** — легкому інструменті для управління проєктами та задачами для невеликих команд, які цінують роботу більше, ніж налаштовування інструментів. Ця сторінка — ваш «операторський посібник»: що вміє система, як її частини поєднуються між собою, та які методології найкраще лягають на її примітиви.

## Що всередині

- **Проєкти** — довготривалі контейнери для пов'язаних задач, кожен зі своєю канбан-дошкою, учасниками, тегами та станом «закріплено».
- **Задачі** — одиниця роботи, живе в одній з колонок дошки, може мати пріоритет, підстатус, одного виконавця, коментарі, вкладення та зв'язки з іншими задачами.
- **Теги** — мітки в розрізі типу сутності (проєкт, задача, сторінка Вікі). Створюються глобально, призначаються в межах кожного скоупу.
- **Опитування** — швидкі асинхронні рішення без зайвих нарад.
- **Форми** — публічні форми збору заявок/відгуків. Подання приходять у розділ Forms Data для тріажу.
- **Вікі** (саме тут ви зараз) — Markdown-сторінки з категоріями, тегами, коментарями та явними «знімками» версій.
- **Користувачі та ролі** — admin / manager / employee, з модерацією при реєстрації.
- **API-токени** — особисті довгоживучі токени виду `otk_…` для програмного доступу. Керування — в профілі.
- **Compass** *(адмін)* — панель системного адміністрування за адресою `/admin/compass`: запуск міграцій, очищення кешу/сесій, скидання версії статичних файлів, обрізання логів активності, перегляд статистики БД, читання логів помилок, керування внутрішнім self-update.

## Денний робочий цикл

Здоровий день в Otack Manager виглядає приблизно так:

| Крок | Де | Що ви робите |
|------|----|--------------|
| 1 | Сайдбар **Проєкти** | Відкрийте свій закріплений проєкт — це ваша «домашня» дошка. |
| 2 | **Проєкти → дошка** | Заберіть із «Backlog» / «To Do» в «In Progress» те, що відповідає поточним пріоритетам. |
| 3 | **Сторінка задачі** | Оновіть підстатус, додавайте коментарі для контексту, прикріплюйте скріншоти/файли. |
| 4 | **Вікі** | Фіксуйте все багаторазове — runbook'и, рішення, поради для онбордингу. |
| 5 | В кінці дня | Перенесіть готове в «Done», залиште короткий standup-коментар у проєкті. |

Цей цикл навмисне короткий. Інструмент окуповує себе лише тоді, коли не заважає кроку 2.

## Методології, що природно лягають на систему

Otack Manager **навмисно не нав'язує методологію**. Ось як на його примітиви накладаються найпоширеніші підходи.

### 1. Kanban

Найкращий, коли робота приходить непередбачувано (підтримка, ops, маркетинг).

- **Колонки** = стадії. Стандартні `Backlog → To Do → In Progress → Done` працюють для більшості команд. Підлаштуйте під свій проєкт — додавайте/перейменовуйте/перевпорядковуйте колонки з меню колонки на дошці.
- **WIP-ліміти** система не нав'язує — домовтесь усно і запишіть у описі проєкту.
- **Пріоритети** задач (`low / medium / high / urgent`, або none) — сигнал, що тягнути далі. Дошка вміє сортувати за пріоритетом через тулбар. Разом із **закріпленими проєктами** ви тримаєте найважливіше зверху сайдбару.

```text
Backlog  →  To Do  →  In Progress  →  Done
   ↑                                    │
   └──── Постійний потік нової роботи ──┘
```

### 2. Scrum-lite (спринтовий ритм без перевантаження ритуалами)

Найкращий, коли планування — у циклах 1-2 тижні.

- Створіть **тег** виду `sprint-N` (наприклад, `sprint-12`) у скоупі задач. Помічайте ним усі задачі спринту.
- Через **Опитування** проголосуйте за обсяг спринту на старті — підсумок зафіксуйте коментарем у задачі планування.
- Наприкінці спринту — пишіть **ретроспективу** в розділі Вікі в категорії `Retros`. Збережіть **знімок** після того, як команда узгодила фінальну редакцію.

### 3. GTD (Getting Things Done)

Найкращий для індивідуального управління навантаженням.

- Один проєкт = ваш inbox. Колонка `Backlog` — це «зловлене, але ще не оброблене».
- В `To Do` переносьте лише те, де ви визначилися з **наступною конкретною дією**.
- **Теги** використовуйте як контексти (наприклад, `home`, `deep-work`, `quick-win`).
- Щотижня очищайте inbox у проєктні дошки — це і є ваш weekly review.

### 4. Особистий щоденний список

Якщо методології здаються важкими, можна простіше:

1. Закріпіть один проєкт `Today`.
2. Зранку перенесіть 3-5 задач в `In Progress`.
3. Увечері закрийте їх або поверніть назад.

Інструмент не докучатиме нагадуваннями. Це навмисно.

## Вікі — найкращі практики

Модуль Вікі (саме там, де ви зараз) призначений для **речей, які доведеться перечитувати не один раз**.

- **Категорії** — плоский список. Не перемудруйте: `Інженерія / Ops / HR / Продажі / Рішення` — достатньо для більшості команд.
- **Теги** працюють по всій Вікі — використовуйте їх для крос-сектних тем (`security`, `oncall`, `customer-X`).
- **Знімки** — явні. На сторінці Versions натисніть *Зберегти знімок* перед великим переписуванням. Знімки — лише для читання історії, **автоматичного відкату немає**. Так задумано.
- **Коментарі** лишайте на сторінці, до якої вони стосуються, а не в чаті. Ви самі через місяць подякуєте.
- **Пошук** регістронезалежний, з підтримкою Unicode, шукає по заголовку і тексту — навіть по частині слова. Комбінуйте з категорією для звуження.

### Перші сторінки, які варто завести

```text
Інженерія
  ├─ Інструкція з деплою
  ├─ Налаштування локального середовища
  └─ Playbook реагування на інциденти

Ops
  ├─ Список постачальників і контактів
  └─ Регулярні зустрічі та їх ритм

HR
  └─ Чекліст онбордингу
```

## Ролі та права

| Роль | Читання | Редагування задач | Управління користувачами | Редагування Вікі |
|------|---------|-------------------|---------------------------|------------------|
| **Admin** | так | так | так | так (і видаляти сторінки + керувати категоріями) |
| **Manager** | так | так | частково | так (редагування + створення + знімки) |
| **Employee** | так (призначені + публічні) | свої задачі | ні | лише коментарі |
| **Pending** | нічого | нічого | нічого | нічого |

Нові реєстрації потрапляють в **Pending** до схвалення адміном. Це навмисно — це тримає робочий простір малим і довіреним.

## Теги — дешевий і потужний крос-зріз

Теги працюють по **проєктах**, **задачах** і **Вікі**, кожен у своїй сфері. Кілька шаблонів, які окуповують себе:

- `fire` — видно одразу по всьому простору, а не тільки в одному проєкті.
- `cust-acme` — все, що стосується клієнта Acme, в одному кліку.
- `area-billing` — теги по зоні коду допомагають інженерам тріажити швидше за читання заголовків.

Тримайте словник тегів маленьким. Стіна тегів гірша за відсутність тегів.

---

## Опитування — асинхронні рішення

Використовуйте Опитування, коли:

- Рішення зачіпає більше ніж 2 людей, але не потребує зустрічі.
- Вам потрібен письмовий слід, хто як проголосував.
- Варіанти можна перерахувати (так/ні, A/B/C, кілька варіантів).

Не використовуйте Опитування для відкритих питань — їх місце в коментарі задачі або в чернетці сторінки Знань.

## Форми — легкий збір заявок

Форми зручні для:

- Звітів про баги від нетехнічних колег.
- Каналів зворотного зв'язку клієнтів.
- HR / запитів на відпустки.

Кожне подання з'являється у **Forms Data**, де менеджер може перевести його в задачу.

---

## Пошук

Поле пошуку у боковій панелі Вікі шукає по **заголовку та тексту**, без врахування регістру, з підтримкою Unicode і пошуком по частині слова. Комбінуйте з категорією, щоб звузити результат. Якщо команда стає великою — спирайтесь більше на теги, ніж на повнотекстовий пошук: вони точніші.

## Налаштування на старті

Якщо ви адмін, який заводить інструмент:

1. **Створіть перший проєкт** в `/projects`. Закріпіть його — це стане «домашньою» дошкою.
2. **Визначте свої колонки**. Стандартних 5 зазвичай достатньо — змінюйте лише якщо є причина.
3. **Створіть базові теги** (пріоритети, зони, клієнти). На старті обмежтесь ~15 тегами.
4. **Запросіть команду**. Вони реєструються, ви схвалюєте їх в `/users`.
5. **Засійте Вікі** хоча б трьома сторінками:
   - Ця сторінка з онбордингом (уже тут).
   - Сторінка про деплой / runbook.
   - Сторінка про норми команди / «як ми працюємо».
6. **Виставте дефолтну мову** в Settings — на робочу мову команди.

## Швидка довідка

| Дія | Де |
|-----|-----|
| Відкрити панель системного адміністрування | `/admin/compass` |
| Створити задачу | Дошка проєкту → `+ Add task` в будь-якій колонці |
| Перемістити задачу | Drag & drop на дошці |
| Коментар до задачі | Сторінка задачі → внизу |
| Фільтр задач по тегу | Чіп тега у верхній частині дошки проєкту |
| Зберегти знімок Вікі | Сторінка Вікі → Versions → *Зберегти знімок* |
| Подивитись API-токени | `/profile` → API tokens |
| Запустити системну дію | `/admin/compass` (тільки admin) |
